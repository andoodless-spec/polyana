# полянка 🌿

Обновлённая версия **1.2** личного сайта: Next.js, React, локальный пиксельный шрифт с кириллицей, Neon PostgreSQL. Репозиторий GitHub не нужен.

## Что изменилось в этом ZIP

- Новое название — **«полянка»**, со строчной буквы: логотип, вкладка браузера, подвал и прикреплённый промпт.
- Меню: ингредиенты и пересчитанные количества идут **вертикальным списком**, каждый продукт на своей строке. Приблизительная калорийность отмечается знаком ≈. Способ приготовления в меню не показывается. PNG использует тот же принцип.
- Картинка в шапке меню: **«Своя картинка меню» → выбрать файл**. Можно заменить или вернуть стандартные цветочки. Она сохраняется в состоянии/JSON-копии и синхронизируется с аккаунтом как другие настройки. При экспорте меню в PNG картинка включается, кнопки управления — нет. PNG/JPEG/WebP/GIF/AVIF до 8 МБ, автоматическое уменьшение до 640×400; GIF неподвижный. Внешние ссылки/SVG не загружаются.
- Покупки: ресторанный лист с рамкой, группами продуктов, количеством и итогами, такой же PNG. Сохраняются ручные продукты, «Куплено», «Есть дома», агрегация и сброс отметок.
- Настоящие предметы на полке и в мини-блоке главной: переплёт книги, VHS с катушками, мульткассета, сериальный бокс, игровой картридж. На телефоне под каждым рядом есть полочка. Объяснения и примеры спрятаны под листиком информации; категории выбираются только под лупой, вкладок нет.
- «Что есть дома»: холодильник с полками, пиксельными упаковками и продуктами. Изменение количества, добавление, «закончилось» и существующее подтверждаемое списание после приготовления сохраняются. Раскладка декоративная, не инструкция по хранению продуктов.
- Новый копируемый промпт **внешнему** ИИ под листиком возле разбора текста. Он уточняет период, число уникальных блюд по категориям, калорийность, порции и предпочтения, предлагает меню, принимает замены, а по команде выдаёт **весь окончательный план** в формате сайта. На самом сайте ИИ по-прежнему нет.
- Массовый импорт поддерживает необязательный раздел **«В меню»** с датами/порциями и отметку **«Ккал приблизительно»**. Можно сохранить только рецепты или сразу добавить подачи в меню. Предварительная проверка и редактирование обязательны; после изменений подтверждение сбрасывается. Неверные даты/количества блокируют сохранение всей подборки.
- По умолчанию старое меню не удаляется. **«Заменить существующее меню на эти даты»** — отдельная отключённая по умолчанию галочка: только перечисленные даты заменяются, прежние позиции уходят в корзину. Одинаковые рецепты и одинаковые подачи повторно используются, исходники/примечания сохраняются. Блюдо с тем же названием, но другим составом, не перезаписывает старое.
- Все доработки 1.1 сохранены: фиксированный дневник без окон/автофокуса и потери текста, поиск под лупой, порядок кухоньки, разные ночные палитры и ручной экспорт дней рождения в .ics.

Существующие API авторизации/данных и схема БД не изменены. Совместимость с сохранёнными данными/резервными копиями первой версии сохранена; база и аккаунты не пересоздаются. Перед обновлением действующего сайта всё равно скачай резервную копию в настройках.

## Что уже есть

- **Мой уголок:** закреплённые мысли, дела, меню/покупки с переключением, незаконченные истории, ближайшие дни рождения. Порядок и видимость блоков настраиваются.
- **Дневник:** страницы, верхние закладки-картинки, стрелки, даты и время, автосохранение текста, отдельные защищаемые «Маленькие трудности», дела, дни рождения, поиск по словам/датам. Экспорт дней рождения в календарь `.ics`.
- **Кухонька:** ручные рецепты, разбор структурированного текста **без ИИ**, оригинал текста, категории, любимые блюда, рандомайзер, поиск по продуктам, исключения, порции, меню, общий список покупок, галочки **«Куплено»** и отметки **«Есть дома»**, запасы и подтверждаемое списание после приготовления, PNG меню/покупок.
- **Полка:** книги, VHS, мультфильмы, сериальные боксы и игры. Незаконченное сверху, отзывы по убыванию рейтинга, отдельная зона без оценки. 1–5 листиков, рецензии и черновики, спойлеры, рекомендации, желание вернуться, поиск и комбинированные фильтры.
- **Настройки:** Шалфей/Мох/Овёс, день/тихий лес/как на устройстве, порядок разделов, текстовые/фотокарточки блюд, идеи для кода, резервная копия и корзина.
- Иконка с полем травы, собственная векторная пиксельная иллюстрация, адаптация 320 px и шире.

## Важно про текущий режим

Без `DATABASE_URL` сайт работает в **явно обозначенном локальном деморежиме**. Примеры записей, блюд и произведений — демонстрационные. Они не являются реальными личными данными или рекомендацией по питанию. Демо хранится только в этом браузере. В настройках → «Аккаунт и данные» можно очистить его.

Личный аккаунт открывает **отдельное пустое пространство**, а не копирует демонстрационные записи. При желании собственные данные можно перенести через JSON-копию. Аккаунты и настоящая синхронизация требуют подключения Neon. На момент передачи исходников соединение с живой базой не проверено: доступ не предоставлен. Публикация в Vercel также требует подключения аккаунта пользователя.

## Локальный запуск

Нужен Node.js 20.9+ (рекомендуется актуальный LTS).

```bash
npm ci
npm run dev
```

Открыть `http://localhost:3000`. Без базы доступно всё локальное демо.

Для локальной работы с облаком создать **непубликуемый** `.env.local`:

```dotenv
DATABASE_URL=postgresql://...
```

Не добавлять эту строку в клиентский код, `NEXT_PUBLIC_*`, архив исходников или переписку.

## Публикация в Vercel + Neon БЕЗ GitHub

### 1. Создать базу

Создать проект PostgreSQL в своём Neon, желательно в ближайшем подходящем регионе ЕС. Взять строку подключения с SSL (`sslmode=require`), предпочтительно pooled connection. Можно также подключить Neon через Marketplace/Storage своего проекта Vercel. Если интеграция создаёт переменную под другим именем, явно добавить `DATABASE_URL` с нужной строкой.

### 2. Создать проект Vercel из папки

В терминале на своём компьютере, из этой папки:

```bash
npm ci
npx vercel@latest login
npx vercel@latest
```

Подтвердить свой аккаунт, создание нового проекта и определённый автоматически Next.js. GitHub не подключается. При желании сначала получить демо без базы.

### 3. Добавить переменную базы

В Vercel открыть проект → **Settings → Environment Variables**, добавить секретную переменную:

- имя: `DATABASE_URL`;
- значение: строка подключения из Neon;
- окружение: как минимум Production; Preview — только если там осознанно нужна эта же база (лучше отдельная ветка Neon для тестов).

**Не пересылать пароль базы в чат.** Настройка выполняется в интерфейсе Vercel.

### 4. Опубликовать production

```bash
npx vercel@latest --prod
```

Vercel выдаст настоящий адрес сайта. Если переменная была добавлена после публикации, обязательно сделать новое развёртывание. Включение переменной само по себе уже работающий deployment не изменяет.

Таблицы `glade_users`, `glade_sessions`, `glade_state`, `glade_auth_attempts` создаются автоматически при первом обращении к аккаунтам. У роли БД должны быть права `CREATE TABLE/INDEX` в выбранной базе.

### 5. Проверить перед личным использованием

1. Настройки → Аккаунт и данные → создать аккаунт.
2. Добавить тестовую запись, дождаться «Всё сохранено в облаке».
3. Войти тем же аккаунтом с другого устройства и проверить запись, темы и отметки покупок.
4. Изменить данные там, вернуться на первое устройство (при фокусе и каждые 15 сек выполняется проверка).
5. Скачать JSON, проверить восстановление на ненужных тестовых данных.
6. Только после проверки переносить чувствительные записи.

## Синхронизация и безопасность

- Доступ к состоянию привязан к пользователю серверной сессии, а не к переданному из браузера ID.
- Пароли: scrypt с индивидуальной солью; токены сессий в БД только в виде SHA-256. Cookie HttpOnly, SameSite=Lax, Secure в production.
- Ограничены попытки входа; изменяющие запросы проверяют origin.
- Состояние версионируется. Конфликт не перетирает данные другого устройства молча: нужно скачать свою копию и явно загрузить облачную.
- Несохранённые изменения дополнительно кешируются в браузере и восстанавливаются после перезагрузки. После успешного выхода кеш аккаунта на устройстве удаляется.
- Защита вкладки «Маленькие трудности» — **только от случайного просмотра**, не отдельный пароль и не шифрование.
- Это **не end-to-end encryption**. Данные доступны авторизованному приложению/оператору БД. JSON-копия тоже не зашифрована. Не оставлять аккаунт открытым на чужом устройстве.
- В первой версии нет подтверждения email и восстановления пароля. Пользоваться сильным уникальным паролем/менеджером паролей. Для широкого публичного запуска нужна доработка аккаунтов, антиспама и восстановления доступа.

## Ограничения первого варианта

- Разбор текста детерминированный: понимает образец, а не произвольную прозу. Проверка и редактирование обязательны, неизвестные данные остаются пустыми. Сам сайт не оценивает калории и не генерирует рецепты. Внешний ИИ по прикреплённому промпту может предложить рецепты и приблизительные расчёты; их нужно проверить. Это не медицинская диета.
- Календарь — экспорт `.ics` с ежегодным повторением и напоминанием, не двусторонняя интеграция и не браузерные push-уведомления.
- Фото автоматически уменьшаются до 640 px и хранятся внутри состояния. Для большой коллекции следующим шагом нужно отдельное object storage и постраничное хранение вместо одного JSON. Серверный предел состояния — около 3.5 МБ; у localStorage есть собственная квота.
- Рабочее облако требует сети. Локальная копия не заменяет отдельную резервную копию. Нет полноценного offline/PWA service worker.
- Количество продуктов из разных единиц объединяется только для совместимых единиц (г/кг, мл/л); «ложки» не превращаются в граммы без данных.
- Восстановление JSON заменяет текущее содержимое после подтверждения, поэтому перед ним стоит скачать актуальную копию.

## Образец текста рецепта

```text
Название: Название блюда
Категория: Горячее
Порции: 2
Ккал на порцию: 350
Ккал приблизительно: да
В меню:
2026-11-02 | 3
2026-11-04 | 2
Ингредиенты:
Название продукта | 200 | г
Другой продукт | 1 | шт
Приготовление:
Твой готовый текст приготовления.

---

Название: Следующее блюдо
...
```

Допустимые категории: Суп, Горячее, Салат, Фастфуд, Завтрак, Выпечка, Другое. Строку калорий можно не писать. Числа и даты в образце — лишь пример формата. «Порции» — базовый выход рецепта, ингредиенты суммарно на этот выход. В «В меню» указаны порции на конкретную дату: сайт сам пересчитает граммовки. Раздел можно пропустить для сохранения только в коллекцию. Формат даты ГГГГ-ММ-ДД, количество порций в подачах больше 0 и до 1000; базовые порции 1–1000. Неверные строки нужно исправить перед импортом.

## Проверки

```bash
npm test
npm run build
# В другом терминале запустить сайт на порту 3000, затем:
npx playwright install --with-deps chromium
npm run test:ui
```

Браузерные проверки: создание и редактирование записи без окна, отсутствие автофокуса, фиксированная высота и полное восстановление длинной записи из 26 страниц, изменение стопки, встроенное редактирование дел/дат, календарь, правильный порядок кухоньки, массовый импорт и сохранение, промпт под листиком, поиск под лупой, отсутствие категорий-вкладок на полке, разные ночные палитры, галочки покупок после перезагрузки, PNG и отсутствие горизонтального переполнения на 320 px.

Дополнительные браузерные тесты 1.2 проверяют реальные рубашки на полке/главной, образцы под листиком, редактирование/удаление запасов, ошибки дат и сброс подтверждения, повторный импорт без дублей, замену только выбранных дат с корзиной, сохранение исходников, вертикальные граммовки, PNG покупок, 320 px и ночной холодильник. Картинка меню проверяется на загрузку, уменьшение, сохранение после перезагрузки, замену/сброс, отказ для неверного/повреждённого/слишком большого файла; наличие картинки в PNG проверяется по пикселю.

Отдельные unit-тесты дополнительно проверяют реальные/високосные даты, дробные порции, атомарный отказ до изменения данных, переиспользование рецептов и сохранение дополнительных исходников. Остальные unit-тесты проверяют пустые значения без выдумывания данных, несколько рецептов, примечания, пересчёт продуктов и ICS. Тест синхронизации использует **mock API**, а не настоящую Neon: сохранение, восстановление pending-правок, конфликт после перезагрузки, явная загрузка облачной версии. Живое подключение Neon ещё требует отдельной проверки после предоставления доступа.
